# Creator Decision Center V1

## Purpose

The Creator Decision Center presents the prioritized, evidence-backed actions
generated by the Creator Decision Engine. It helps a creator understand what was
detected, why it matters, what to do, what impact is expected, and how the result
should be measured.

The page does not recalculate priority, confidence, evidence, or business
conclusions. It is a presentation layer over the public Core result.

## Route

```text
/{locale}/decisions
```

Supported locales are `es`, `en`, `fr`, and `pt-BR`. The sidebar owns the active
localized navigation entry.

## Data flow

```text
isolated demonstration analytics fixture
  -> executeYouTubeIntelligence
  -> generateCreatorDecisionsFromYouTubeAnalytics
  -> createCreatorDecisionCenterViewModel
  -> CreatorDecisionCenter
```

The current Blueprint application has no authenticated or persisted creator
analysis. The feature therefore reuses the existing Analyzer demonstration
scenarios and adds one isolated `no-decisions` scenario. Every scenario executes
the real analytics and decision engines; no decision is stored in a fixture.

The page explicitly labels the source as demonstration data and must not be
presented as live creator analysis.

## View Model responsibilities

The View Model:

- resolves domain message keys through the active Blueprint dictionary;
- uses the domain fallback only when a key is unavailable;
- formats dates, evidence values, metrics, confidence, category, and priority;
- preserves the engine order;
- applies presentation-only priority and category filters;
- distinguishes populated, empty, insufficient-data, and controlled error states.

It does not change scores, priority, rule identifiers, evidence, thresholds, or
expected impact.

## Translation strategy

Engine messages use stable `creatorDecisions.*` keys. Each Blueprint dictionary
contains the same key contract. Variable interpolation occurs after lookup. The
English `defaultMessage` carried by the domain remains a safe fallback, not the
primary translation source.

All page labels, controls, states, rule explanations, evidence labels, metric
labels, and alternatives are translated in the four supported locales.

## Interaction and accessibility

Priority and category filters use URL search parameters and native form controls.
Filtering never reorders decisions. Evidence, confidence, and alternatives use a
native `details` disclosure. Recommended actions remain visible without opening
the disclosure.

The page uses semantic headings, articles, lists, definition lists, textual
priority and confidence labels, visible focus states, and responsive layouts.
Color is supplementary and never the only status indicator.

## Replacing demonstration data

When persisted creator analysis becomes available, replace only the source
selection in `app/[locale]/decisions/page.tsx`:

1. load the authorized normalized analysis result;
2. pass it to the existing public Decision Engine API;
3. keep the View Model and component contracts unchanged;
4. remove the demo notice only when the source is verifiably live.

No component or domain rewrite should be required.

## Known limitations

- Decisions are read-only and are not persisted.
- There is no acceptance, dismissal, or completion workflow.
- Filters are limited to priority and category.
- The page does not add growth or monetization decisions that the engine cannot
  support.
- The loading boundary may be brief with local deterministic fixtures.
